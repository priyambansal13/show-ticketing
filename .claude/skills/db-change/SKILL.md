# Database / storage change

## Pick the right store (see CLAUDE.md "Where data lives")
- Money, seats, bookings, users, audit → **PostgreSQL**
- Catalog (venues, layouts, events, shows) → **MongoDB**
- Ephemeral / fast-read / TTL → **Redis**
- Cross-module async facts → **Kafka topic** (produced via outbox)

## PostgreSQL (Prisma)
1. Edit `ticketing-api/prisma/schema.prisma`. Models PascalCase, fields camelCase with `@map("snake_case")`, tables `@@map("snake_case")`.
2. Money `@db.Decimal(10, 2)`; timestamps `@db.Timestamptz(6)`; ids `@db.Uuid @default(uuid(7))` (time-ordered; generated by Prisma, so raw-SQL inserts must supply the id).
3. Add constraints the invariants depend on: `@@unique([showId, seatId])`, unique `idempotencyKey`, unique `providerOrderId`, etc. Add indexes for every hot `WHERE` (e.g. `@@index([showId, status])`).
4. `pnpm db:migrate --name <verb_noun>` (add `--create-only` when hand-editing SQL); review the generated SQL. Hand-edit for things Prisma can't express (partial indexes, CHECK constraints) and keep them in the migration.
5. Migrations must be backward compatible with the running code (add nullable → backfill → enforce).
6. Update seed script if needed.

## MongoDB (Mongoose)
1. Schema in `modules/<domain>/schemas/*.schema.ts` with `@Schema({ timestamps: true })`.
   - **Every `@Prop` declares an explicit `type`** (`String`, `Number`, `Date`, `Types.ObjectId`, `[SubSchema]`, `Map`). Vitest and tsx compile with esbuild/oxc, which do not emit decorator metadata — without explicit types the schema fails to load outside `nest build`.
   - Money in Mongo is configuration only and stored as **integer minor units** (paise); the selling price lives in Postgres `show_seats.price`.
   - Server-built query operators (`$text`, `$in`, date ranges) are wrapped in `mongoose.trusted()`; request data never is (see `security-standards`).
2. Declare indexes in the schema (`city + startsAt`, `eventId`, text index on `title, genres`, `2dsphere` on `geo`).
3. Layouts are versioned — never mutate a layout that an on-sale show references; create a new `version`.

## Redis / Kafka
- New key patterns and topics must be added to the plan tables (§4.3, §4.4) with type, TTL, and purpose.
- Kafka topic names `domain.event_past_tense`; payloads have a zod schema in `ticketing-api/src/events/contracts/`.

## Always
- Update `docs/IMPLEMENTATION_PLAN.md` §4 to match.
- If the change touches `show_seats`, `bookings`, or `payments`, follow `booking-integrity`.
